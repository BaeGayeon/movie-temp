# bae-movie-temp (임시 이름)

티빙/웨이브/쿠팡플레이처럼 텔레파티가 지원하지 않는 OTT에서 같이 영상을 볼 수 있는 크롬 확장 프로그램.
각자 자기 계정으로 재생하고, 재생/일시정지/시크 **상태만** 동기화한다. 자세한 내용은 [SPEC.md](SPEC.md).

앱 이름은 `extension/config.js`의 `APP_NAME`과 `extension/manifest.json`의 `name` 두 곳에서만 관리한다.

## 서버 실행

```bash
cd server
npm install
npm start          # PORT 환경변수 사용, 기본 8080. GET /health 제공
npm test           # WebSocket 클라이언트로 방 생성/참가/중계 등을 검증
```

서버 주소는 `extension/config.js`의 `SERVER_URL`(개발용 `ws://localhost:8080`).

## 크롬에 확장 프로그램 로드

1. `chrome://extensions` → 우상단 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램을 로드합니다** → `extension/` 폴더 선택
3. `file://` 로 로컬 mp4를 직접 열어 테스트하려면 확장 프로그램 상세에서 **파일 URL에 대한 액세스 허용**을 켠다.

## 크롬 프로필 두 개로 테스트

1. 서버 실행 후, 크롬 프로필 A·B 각각에서 위 방법으로 확장 프로그램을 로드한다.
2. 프로필 A: `<video>`가 있는 페이지(예: mp4 URL을 직접 열기)에서 확장 아이콘 → **방 만들기**.
3. **초대 링크 복사** → 프로필 B에서 그 링크를 열면 "같이 보기 초대" 배너가 뜬다 → **참가**.
   (또는 B에서 같은 영상 페이지를 열고 팝업에 방 코드 입력)
4. 한쪽에서 재생/일시정지/시크 → 다른 쪽에 반영되는지 확인.
5. 팝업의 **조작** 드롭다운(방장만 보임)으로 "방장만 조작"을 켜고 B에서 조작해 본다.
6. (2단계) 방장 팝업의 **카운트다운 시작**(3/5/10초) → 모든 참가자 화면에 "3, 2, 1, 재생!"이 뜨고 같은 순간에 재생된다.
7. (2단계) 한 명이 버퍼링하면 나머지가 멈추고 "OO님이 버퍼링 중…"이 뜬다. 해소되면 함께 재개, 최대 15초까지만 기다린다.

방은 확장 프로그램이 "방을 만들거나 참가한 탭"에 묶인다. 그 탭을 닫으면 방에서 나가고, 새로고침하면 같은 방으로 복귀한다.

## 설계 메모

### 서비스 워커 vs offscreen document → 서비스 워커 선택

WebSocket 연결을 `background.js` 서비스 워커에서 직접 맺는다.

- Chrome 116+ 에서는 WebSocket 으로 메시지를 주고받는 동안 서비스 워커의 유휴 타이머가 리셋된다. 20초마다 `ping`을 보내므로(30초 유휴 종료보다 짧음) 연결이 유지된다.
- 그래도 워커가 종료/재시작될 수 있으므로, 방 정보(`roomCode`, 묶인 탭, 영상 상태 등)와 `userId`를 `chrome.storage.local`에 저장하고, 워커 시작 시 복구해 재연결·재입장한다. `chrome.alarms`(30초 주기)로도 깨워 연결 상태를 점검한다.
- offscreen document 는 별도 문서·권한·생명주기를 관리해야 하고, WebSocket 유지를 위한 정식 `reasons` 도 마땅치 않아 이 규모에서는 복잡도만 늘어난다. 유지가 불안정하다는 증거가 나오면 그때 전환한다.

### 무한 루프 방지

원격 동작을 `<video>`에 적용하기 직전 "이 이벤트는 내가 일으킨 것" 토큰(1.5초 유효)을 남기고, 뒤따르는 `play`/`pause`/`seeked` 이벤트가 오면 토큰을 소비하며 서버로 보내지 않는다. 실제로 상태가 바뀔 때만 토큰을 만든다(이미 재생 중이면 `play` 토큰 없음).

### 2단계 동작 방식

- **카운트다운:** 서버가 `startAt`(서버 시각)을 정해 방 상태를 "startAt 에 재생 시작"으로 저장한다. 각 클라이언트는 `serverOffset`으로 자기 시계를 서버 시계로 환산해 같은 순간에 `play()`한다. 카운트다운 중 입장한 사람도 같은 상태를 받아 함께 시작한다.
- **시계 보정:** 20초마다 `ping{clientTime}` → 서버가 `server_time{serverNow, clientTime}` 응답. RTT 의 절반을 편도 지연으로 보고, 최근 5개 표본 중 RTT 가 가장 작은 것을 쓴다.
- **버퍼링 대기:** `waiting` 이벤트가 0.5초 넘게 이어지면 `buffering` 보고 → 서버가 방을 정지(`autoPaused`)하고 `buffer_state` 로 대기자 목록 전달 → 모두 준비되면 0.5초 뒤 시각으로 재개를 예약해 함께 재생. 상한 15초가 지나면 대기자를 두고 강제 재개. 사용자가 직접 재생/일시정지하면 자동 재개하지 않는다(시크는 영향 없음).
- **싱크 자동 보정:** 재생 중 5초마다 `sync_report`. 서버는 **방장**의 보고만 기준점으로 삼아 다른 참가자에게 `video{action:"sync"}`로 전달한다. 각 클라이언트는 기준 위치와의 차이가 0.3초 미만이면 그대로, 0.3~2초면 `playbackRate`를 0.95~1.05로 조정, 2초 초과면 시크한다. 방장은 보정하지 않는다.

### 3단계 동작 방식

- **프로필:** 팝업의 "내 프로필"에서 이름(최대 16자), 이모지 프사 + 배경색, 채팅 색을 고른다. `chrome.storage.local`에 저장되고, 입장/재접속 때 서버에 등록(`profile_update`), 바꾸면 방 전체에 전파(`profile_updated`). 프로필이 없으면 서버가 임시 이름(`게스트1234`)과 기본 색을 준다.
- **채팅:** 화면 오른쪽 사이드바. 접기(—), 투명도 슬라이더, 왼쪽/아래 가장자리 끌어서 크기 조절(설정은 `chrome.storage.local`에 기억). 메시지에는 `userId`만 붙고 이름/프사/색은 참가자 목록에서 찾아 그린다(그래서 프로필을 바꾸면 이전 메시지도 같이 바뀐다). 최근 100개는 background 가 보관해 새로고침 후에도 복구된다.
- **접힌 상태 알림:** 말풍선(💬)에 안 읽은 수 배지 + 토스트. 말풍선에 마우스를 올리면 리액션 버튼이 나온다.
- **입력 중 표시:** 입력하면 `typing` 전송(2초 간격 디바운스), 3초간 입력이 없으면 자동 해제. 받는 쪽도 3초 뒤 자동으로 지운다.
- **리액션:** ❤️😂😱👍👏🔥😢🎉 (서버 허용 목록). 영상 쪽에 잠깐 떠올랐다 사라진다. 서버가 사용자당 초당 3회로 제한한다.
- **전체화면:** UI 호스트를 전체화면 요소 안으로 옮겨 보이게 한다. 전체화면 요소가 `<video>`/`<iframe>` 자체이면 자식을 그릴 수 없어 보이지 않는다(알려진 한계).
- **보안/제한:** 사용자 텍스트는 전부 `textContent`로만 렌더링(XSS 방지). 서버가 채팅 300자·빈도(버스트 5개, 평균 초당 1.5개), 프로필 이름/색/이모지 형식을 검증한다. 입력창에서 키 이벤트를 막아 사이트 단축키(스페이스=재생 등)가 동작하지 않게 했다.

### 4단계 동작 방식 (이미지 프사 + 추가 기능)

- **이미지 프사:** 팝업 "내 프로필 → 사진 올리기". 내 컴퓨터에서 64×64 로 중앙 크롭해 WebP(안 되면 JPEG) 데이터 URL 로 만들고 20KB 이하가 될 때까지 품질을 낮춘다. 별도 파일 업로드/저장소는 없다. 프로필의 일부로 서버에 보내지고, 서버는 방 메모리에만 두며 참가자에게 전달한다. 서버가 `data:image/(webp|jpeg);base64,` 형식, 20KB 상한, 파일 헤더(JPEG `FFD8FF` / WebP `RIFF…WEBP`)가 선언한 형식과 일치하는지 검증한다. 이미지 프로필 변경은 크기가 커서 증폭 전파되므로 빈도를 엄격히 제한한다(버스트 3회, 평균 5초에 1회). 화면에는 페이지 CSP(img-src)에 막히지 않도록 `<img>` 대신 canvas 로 그린다.
- **이모지 전체 선택:** `shared/emoji-picker.js`(그룹 탭 + 최근 사용). 프사(팝업), 채팅 입력(😊), 리액션(＋)에서 쓴다. 서버는 `\p{RGI_Emoji}` 한 개(국기, 키캡, ZWJ 조합 포함)면 허용하고 텍스트는 거부한다. 일부 OS 에서 깨져 보이지 않도록 Emoji 14.0 이하만 목록에 넣었다(피부색 변형 제외).
- **채팅 배치:** 헤더의 ◨ / ❐ 버튼으로 전환. *떠 있는 창*은 헤더를 끌어 이동, 가장자리/모서리를 끌어 크기 조절. *오른쪽에 붙이기*는 채팅이 화면 오른쪽 전체 높이를 차지하고 **사이트 화면은 그 왼쪽 영역에 맞게 줄어든다**(화면 분할).
  - 기본은 **전체 축소**: 영상이 `vw`/`position: fixed`로 화면 전체에 깔린 OTT 사이트에서도 영상과 컨트롤이 함께 줄어든다. 스크롤이 없는 페이지(시청 화면)는 `<html>`에 `transform: scale`을 걸어 줄이고 **세로 가운데**에 놓는다. 스크롤되는 페이지는 CSS `zoom`을 쓴다(`transform`은 `fixed` 요소를 문서에 묶어 스크롤에 딸려 나가게 해서 영상이 사라지기 때문). `zoom`은 위쪽 정렬이다. 페이지에 스크롤이 생기면 자동으로 `transform` → `zoom`으로 바꾼다. 줄이면 글자도 작아진다.
  - ⚙ 설정의 "붙일 때 화면"에서 **폭만 줄이기**를 고를 수도 있다(`<html>` 폭만 줄임). 반응형 레이아웃 사이트에서는 자연스럽지만, `vw`/`fixed` 요소는 줄어들지 않고 채팅 아래에 깔린다.
  - 사이트 화면이 변환(transform)되어도 채팅이 같이 줄어들지 않도록, 채팅 UI는 브라우저 **최상위 레이어(Popover API)**에 올린다. 전체화면에서는 페이지를 줄일 수 없어 영상 위에 겹쳐 보인다. 채팅을 접거나 방을 나가면 `<html>` 스타일을 원래대로 복구한다.
- **시간 표시:** 메시지 이름 옆에 `오후 9:41 · ▶ 12:34`. 앞은 작성 시각, 뒤는 보낸 시점의 영상 재생 위치. 재생 위치는 이 프레임의 실제 `<video>`에서 읽고, 영상이 iframe 안에 있으면 그 프레임이 1초마다 `postMessage`로 알려준 값을 쓴다(둘 다 없을 때만 방의 마지막 이벤트 기준 타임라인으로 계산). ⚙ 설정에서 각각 켜고 끈다.
- **방을 만든 사람의 영상:** 방을 만들면 서버의 초기 상태(정지, 0초)로 내 영상을 되돌리지 않고, 내 영상의 현재 상태(재생 여부, 위치)로 방을 시작한다. 이후 입장하는 사람은 거기에 맞춰진다.
- **복사:** 헤더의 방 코드 칩을 누르면 코드 복사, ⚙ 설정에서 초대 링크/방 코드 복사. 팝업에도 "코드 복사" 버튼.

### 광고 구간

OTT 광고는 사용자마다 다른 영상이다. 광고 중에 서로의 재생/일시정지/시크를 주고받으면 한쪽 광고가 멈추거나 되감긴다. 그래서 **광고 구간에서는 동기화를 완전히 끈다**(보내지도, 받지도 않는다).

- **판별:** 어댑터의 `isAd(video)`. 기본 어댑터는 영상 길이가 90초 미만이면 광고로 본다(광고는 보통 15~60초, 본편은 훨씬 길다). 같은 `<video>`의 `src`가 광고 ↔ 본편으로 바뀌는 신호(`durationchange`/`loadedmetadata`/`emptied`)와 1초 주기로 다시 판단한다. 사이트별로 더 정확한 판별이 필요하면 전용 어댑터에서 `isAd`를 덮어쓴다.
- **광고 중:** 내 조작/버퍼링/위치 보고를 방에 보내지 않고, 방에서 오는 재생/일시정지/시크/카운트다운 적용도 건너뛴다. 화면에 "광고 중이라 같이보기 동기화를 잠시 멈췄어요"를 표시한다. 채팅의 재생 시각도 붙이지 않는다.
- **광고 끝:** 본편으로 돌아오면 방 상태(다른 사람의 현재 위치)에 다시 맞춘다. 직후 1.5초는 사이트가 본편을 스스로 시작/시크하는 이벤트를 방에 보내지 않는다.
- **소스 교체 중 이벤트 차단:** 메타데이터가 오기 전(`duration`이 `NaN`)에 발생하는 이벤트는 방에 보내지 않는다. 광고로 `src`를 바꾸는 순간 `play`(0초)가 전파돼 상대 본편이 처음으로 되감기는 것을 막는다.
- **끄기:** 팝업 "동기화 설정 → 광고 구간은 동기화에서 제외". 90초보다 짧은 영상으로 테스트할 때는 꺼야 한다. 켜 두면 90초 미만 영상은 동기화되지 않는다.
- **한계:** 광고가 본편과 같은 길이로 이어 붙은 영상(서버 측 광고 삽입)이거나 길이가 90초 이상인 광고는 구분하지 못한다. 전용 어댑터로 해결한다.

### 프로토콜 추가 사항 (SPEC 대비)

- 참가자 정보(`participants[]`, `user`)가 `{ id, name, avatar, color }`, `avatar.kind` 는 `emoji` 또는 `image`
- `chat`에 선택 필드 `videoTime`(보낸 시점의 재생 위치, 초). 클라이언트 → 서버, 서버 → 클라이언트 모두
- `profile_update`만 메시지 크기 상한이 큼(40KB, 나머지 4KB). `reaction`은 이모지 1개면 무엇이든 허용
- `chat`, `profile_updated`, `reaction`은 보낸 사람 본인에게도 전달(로컬 에코 없이 순서 보장), `typing`은 제외


- `ping`에 선택 필드 `clientTime`, 서버 → 클라이언트 `server_time{serverNow, clientTime}`
- `buffering`에 선택 필드 `time`(버퍼링 시작 위치), `buffer_state`에 `video`(서버가 정한 방 영상 상태) 포함
- `room_state`에 `waitingIds` 포함
- 서버 → 클라이언트 `video.action` 에 `"sync"` 추가(기준점 갱신 전용)


- 서버 → 클라이언트 `mode_changed { mode }`: 권한 모드 변경 알림
