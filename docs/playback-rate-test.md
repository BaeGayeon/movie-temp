- 기존 결함: 방 밖에서도 correctDrift가 매초 1배속으로 초기화. 방 안에서도 배속 상태·중계·배속을 반영한 시간 계산이 없음.

## 검증

1. `cd server && npm test`: 84개 테스트. 기존 76개 + WebSocket 배속 3개 + 실제 콘텐츠 함수 회귀 5개.
2. 로컬 실제 RoomManager/WebSocket 서버에 서로 독립된 두 브라우저 플레이어를 연결하고 변경한 `extension/content/main.js`를 실행했다. Chrome 확장 background 메시지 전달 계층은 테스트 어댑터로 대체했다. `server/test/browser`로 재현할 수 있다.
3. 2배속 연속 재생: 방장 실제 49.504초 동안 영상 99.017초, 참가자 49.499초 동안 영상 99.007초 진행. 둘 다 playbackRate 2.0, 측정 시점 위치 차이 약 0.003초. 이 수치는 해당 로컬 시험의 관측값이며 인터넷 환경의 오차 보장은 아니다.
4. 일시정지 후 두 플레이어 모두 paused=true, rate=2. 60초 탐색 후 둘 다 currentTime=60, rate=2.
5. 참가자 새로고침: 정지 상태와 재생 상태 모두 rate=2와 방 위치 복원. 재생 중 재입장 측정 위치는 방장 117.715초 / 참가자 117.686초.
6. 3초 카운트다운 후 두 플레이어 모두 2배속 재생. 참가자가 1.5배속으로 바꾸면 방장도 1.5배속, 방장이 다시 2배속으로 바꾸면 양쪽에 반영.
7. 자동 보정 중 배속 재전송 루프 없음: 방장의 실제 사용자 변경 2회 전송, 재입장한 참가자의 내부 변경 전송 0회. 방장 전용 권한, 잘못된 배속, 버퍼링 후 재개는 자동 테스트로 검증.

## 실제 웨이브 로컬 방 시험 (2026-10-22)

- PR 확장을 웨이브에만 적용하고 로컬 `127.0.0.1:8080` 서버에 연결했다. Chrome에서 로그인한 웨이브 영화 「황해」의 실제 `<video>` 1개와 독립된 WebSocket 사용자 ID를 가진 Node 시험 참여자 1개로 방을 구성했다. 두 번째 실제 웨이브 계정/기기는 사용하지 않았다.
- 시험 참여자가 방 상태를 12:30, 일시정지, 2배속으로 지정하자 웨이브 영상은 `paused=true`, `playbackRate=2`, `currentTime=750`을 보였다. 시험 참여자의 재생 명령 뒤에는 `paused=false`, `playbackRate=2`가 유지됐다.
- 재생 중 두 관측값은 벽시계 17.750초 간격에 영상 시간 761.745초 → 797.175초였다. 영상 35.430초 진행으로 약 1.996배속이다.
- 웨이브 플레이어에서 X 1.5, X 2.0을 직접 선택했을 때 실제 `video.playbackRate`가 각각 1.5, 2였고 서버 쪽 시험 참여자가 `rate: 1.5`, `rate: 2` 메시지를 받았다. 2배속 상태의 일시정지/재생 메시지도 `rate: 2`로 전달됐다.
- 시험 종료 후 로컬 서버를 중지하고 Chrome 설치본의 파일을 시험 전 백업과 바이트 단위 해시로 대조해 복원했다. 확장 관리 화면에서 원래 이름 `bae-movie-temp (배무템)`과 새로고침 완료를 확인했다.
