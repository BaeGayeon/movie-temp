# 배포 체크리스트 (까먹기 쉬운 것들)

## 배포할 때
- [ ] **서버와 확장은 같이 배포한다.** `create_room`/`join_room` 에 `secret` 이 없으면 서버가 조용히 무시한다 → 구버전 확장은 방을 못 만든다. (`room_idle_closed` 도 구버전 확장이 처리 못 함)
- [ ] 스토어에 올린 뒤 확장 **ID(32자)** 를 알게 되면 Render 대시보드 → Environment 에 `EXTENSION_ID` 를 넣는다. 비워 두면 아무 확장의 접속이나 받는다(웹페이지의 접속은 어느 쪽이든 막는다).
- [ ] `TRUST_PROXY=1` 은 `render.yaml` 에 이미 있다. 프록시 없는 곳(로컬, 다른 호스팅)에서는 켜지 말 것.
- [ ] 스토어 빌드: `node tools/build-store.mjs --server wss://내서버` (개발용 주소가 manifest 에서 빠지는지, `wss://` 인지 확인).
- [ ] `https://서버/health`, `https://서버/privacy` 가 열리는지 확인.

## 배포 직후 확인
- [ ] **접속자별로 IP 가 구분되는지**: 서버는 `X-Forwarded-For` 의 *마지막* 값을 IP 로 쓴다. Render 앞단이 항상 같은 값(프록시 IP)을 넣으면 모든 사람이 한 IP 로 묶여 IP 별 제한(연결 20개, 방 만들기 분당 10회, 참가 실패)이 한꺼번에 걸린다. 두 기기로 동시에 방을 만들어 보고, 이상하면 로그/헤더를 확인.
- [ ] 스토어에서 설치한 확장으로 방 만들기 → 다른 기기로 참가 → 재생 동기화가 되는지(개발용과 확장 ID 가 다르다).
- [ ] 서버를 재배포해도 방이 복구되는지(`server_restarting`).

## 바꾸면 같이 고칠 것
- `server/src/protocol.js` ↔ `extension/shared/protocol.js` 는 동일해야 한다(서버 테스트가 비교).
- 문구는 ko/en 같이(`server/test/i18n.test.js`).
- 서버/기기에 보관하는 정보를 바꾸면 개인정보 페이지(`server/public/privacy*.html`)도.

## 알려진 한계 (일부러 안 고친 것)
- `web_accessible_resources`: 지원 사이트가 확장 설치 여부를 알아낼 수 있다. 콘텐츠 스크립트가 쓰는 파일이라 줄이면 깨질 수 있어 그대로 둠.
- 방 복구(서버 재시작 뒤 `create_room` + `roomCode`): 비밀번호 없는 방은 복구 요청을 가장 먼저 보낸 사람이 방장이 된다. 방 코드를 아는 사람이 재시작 직후에 먼저 보내면 방장을 차지할 수 있다(비밀번호 방은 비밀번호를 알아야 한다).
- 방 코드를 아는 사람은 비밀번호 없는 방에 누구나 들어올 수 있다(링크를 같이 볼 사람에게만 공유).
